# OpenRobot-One 72 小时求职闭环设计

## 1. 目标

在 72 小时内把 OpenRobot-One 转化为可投递、可演示、可追问的求职作品，并同步启动真实岗位投递。

岗位范围固定为：

- 主投：技术支持、项目交付、实施、FAE、应用工程。
- 次投：机器人整机测试、系统测试、功能测试、硬件测试。
- 补充：系统集成、技术销售、售前、解决方案。
- 排除：ROS、C++、嵌入式、算法、视觉、测试开发等编码主导岗位。

本周期不以完成 SLAM、Nav2、视觉、LLM 或完整产品路线为目标。项目只证明候选人能够完成系统搭建、软硬件联调、测试验证、故障定位、安全设计和技术交付。

## 2. 选择方案

采用“真机优先、仿真兜底、投递并行”的双轨方案。

真机轨优先建立以下证据链：

```text
PC 控制/测试程序
  -> UART 协议
  -> STM32F407
  -> 2 x DRV8871
  -> 双电机
  -> 编码器反馈
  -> 速度测试与安全停车
```

仿真轨维持以下可复现证据链：

```text
/cmd_vel
  -> Gazebo 差速底盘
  -> /odom、/tf、/joint_states、/scan
  -> SLAM Toolbox
  -> /map 与 map -> odom
```

真机轨遇到未确认电气参数、引脚冲突、供电或驱动能力不足、编码器电平不明等安全阻塞时，不猜测参数、不强行通电，立即转入仿真复验、协议测试、异常测试、文档和投递工作。真机问题保留为有证据的阻塞记录和排障案例。

## 3. 成功标准

72 小时结束时至少满足：

1. 技术支持/交付版和机器人测试版两份一页中文简历可投递。
2. 完成不少于 30 个高匹配岗位投递，并记录 JD、版本、时间和反馈。
3. 生成一段 60–90 秒项目演示视频；优先真机，真机未安全通过时使用仿真并明确标注。
4. 提供实际运行命令、原始测试结果和未验证项，不把静态检查写成实测通过。
5. 完成系统架构图、测试报告和故障排查手册。
6. 真机至少形成一个真实可验证里程碑：板级 UART、编码器读取、低速运动或通信超时停车。完成层级按实际结果表述。
7. 候选人能在 5 分钟内讲清系统链路、测试方法、一次故障定位和安全机制。

## 4. 真机安全门

### Gate H0：装备与接线

必须确认限流电源、保险丝或等效保护、总电源开关、万用表、公共地、驱动器 VM 去耦以及轮子架空条件。任一项缺失时不得进行电机通电测试。

### Gate H1：电气参数

必须确认电机供电范围、启动/堵转风险、两块 DRV8871 的模块版本与限流/散热能力、编码器供电和输出电平。未知项保持 UNKNOWN，不用推测值填入固件。

### Gate H2：引脚与板级基线

按实物 DRV8871 模块控制逻辑冻结两路电机控制与编码器定时器引脚，不占用 PA13/PA14、PA9/PA10 和 PC13。先在不接电机驱动的状态下验证 STM32 下载、LED 初态和 USART1 115200 8N1。

### Gate H3：运动测试

只有 H0–H2 全部通过，才允许轮子架空、限流、低占空比地进行单电机和双电机正反转测试。方向或编码器符号异常时立即停车。

### Gate H4：闭环测试

只有编码器计数稳定、每轮计数有实测记录且开环运动安全，才进入速度闭环。只做三档目标速度，不做位置环、导航或自动接近。

## 5. 72 小时时序

### 0–12 小时：建立可信基线

- 保存并分类当前工作树变更，明确哪些是已完成成果、哪些是未验证修改。
- 启动 Docker，运行 ROS 2 依赖安装、构建、测试和结果汇总。
- 复验 Gazebo、LaserScan、SLAM 和 TF 所有权，保存原始日志。
- 核对真机硬件、工具、接线和 UNKNOWN 参数，完成 H0/H1 检查表。
- 生成技术支持/交付版和机器人测试版简历初稿。

产物：构建测试记录、仿真复验记录、硬件检查表、两份简历初稿。

### 12–24 小时：板级与通信优先

- 完成 H2，引脚冻结前不驱动电机。
- 验证 STM32 下载、板级状态和 UART 双向通信。
- 冻结最小协议字段和一组 PC/STM32 一致的测试向量。
- 录制第一版视频；真机进展不足时先录仿真版本。
- 第一批投递 10–15 个中型机器人、自动化或智能制造企业岗位。

产物：引脚表、UART 证据、协议样例、第一版视频、投递记录。

### 24–48 小时：真机最小运动闭环

- H0–H2 通过后执行 H3：单电机、双电机、前后左右和停止。
- 读取左右编码器，记录方向、计数和异常现象。
- 若编码器稳定，进入 H4，完成三档速度的目标值与实际值采样。
- 若任一安全门失败，转做协议解析、错误帧、超时停车、仿真回归和排障记录。
- 根据真实 JD 定制简历并完成第二批 10–15 个投递。

产物：真机运动/编码器视频，或协议与故障测试证据；测试数据；第二批投递记录。

### 48–72 小时：故障与交付闭环

- 完成通信超时停车；条件允许时验证串口断开、错误帧和编码器异常。
- 生成真实测试曲线；无可靠速度数据时不生成或虚构 PID 指标。
- 完成 README 展示入口、测试报告、Troubleshooting 手册和 5 分钟项目讲稿。
- 用真实结果更新简历，完成第三批投递，使总量不少于 30 个。
- 最终检查 Git 状态、差异、测试结果、视频链接和所有未验证项。

产物：最终演示、测试报告、排障手册、项目讲稿、简历和投递台账。

## 6. 测试与证据规则

证据按以下等级标注：

- 实际运行并通过：保留命令、时间、原始输出、照片或视频。
- 仅静态检查：说明检查范围，不写成运行通过。
- 未运行：说明缺少的环境、硬件、安全条件或时间。
- 运行失败：保留失败输出、定位过程、结论和下一步。

真机测试优先覆盖正常输入、边界输入、错误输入、通信中断和恢复行为。所有速度、误差、超时和成功率只能引用真实测量结果。

## 7. 求职材料结构

技术支持/交付版突出：

- 软硬件联调、UART、Linux、部署、故障定位、文档、培训与现场适应能力。

机器人测试版突出：

- 测试设计、编码器与电机验证、异常帧、超时停车、测试报告、问题复现和回归。

销售/售前仅在主闭环完成后补充一份 5 页以内的方案案例，内容限定为需求、方案、选型、成本、优缺点和升级路线，不声称存在真实客户。

## 8. 范围外事项

72 小时内暂停：

- Nav2、AMCL、视觉、YOLO、LLM、语音。
- FreeRTOS、CAN、Modbus、micro-ROS、`ros2_control`。
- 位置环、复杂路径规划、自主导航和大规模重构。
- 为增加简历关键词而创建无法演示或解释的新模块。

## 9. 风险与降级

- Docker 或 ROS 环境失败：保留日志并修复最小阻塞；求职材料和硬件检查并行推进。
- 硬件参数无法确认：停止电机通电，以 UART、协议、仿真、测试设计和排障记录完成闭环。
- 编码器不稳定：不做 PID，不写速度精度；转为编码器故障定位案例。
- 真机进度超时：24 小时必须有第一批投递，48 小时必须有可展示视频，项目不得阻塞投递。
- 当前工作树较脏：不覆盖、不删除用户现有修改，不在未授权情况下提交或推送。
