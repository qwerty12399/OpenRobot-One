# H2 UART 板级验收设计

> 历史设计说明：H2 UART目标和结果继续有效；其中“断开DRV8871”应按当前方案理解为“两块IBT-2/BTS7960及两台电机动力全部断开”。

## 目标

在不连接两块 DRV8871、电机和编码器的前提下，为 STM32F407ZGT6 板级固件加入可重复验证的原始 UART 双向通信能力，形成可用于项目验收的真实证据。

## 范围

- USART1 使用 PA9/PA10、115200 8N1。
- 固件启动后发送 `H2-READY\r\n`。
- 收到完整的 `H2-PING\r\n` 后发送 `H2-PONG\r\n`。
- 未知命令或超长输入发送 `H2-ERR\r\n`。
- 接收缓冲区固定为 32 字节；不使用动态内存。
- 只修改 STM32CubeMX `USER CODE` 区域。
- PC13 保持高电平，低有效状态灯保持关闭。
- 未完成命令在 500 ms 内没有收到新字节时静默丢弃。
- UART 接收发生奇偶校验、帧、噪声或溢出错误时清空 HAL 错误标志和解析状态。

## 非目标

- 不实现正式二进制协议、CRC、心跳或通信看门狗。
- 不配置 PWM、方向、STBY、编码器或任何电机输出。
- 不把 H2 ASCII 命令声明为正式 ROS 2 与 STM32 协议。

## 数据流与错误处理

主循环以有限超时逐字节轮询 USART1。回车被忽略，换行结束一条命令。命令长度超过缓冲区后丢弃至下一换行并返回一次 `H2-ERR`，防止越界和残留字节被误解析。每个有效接收字节刷新空闲计时；未完成命令超过 500 ms 后清空且不发送额外响应。HAL 接收错误同样清空解析状态，保证下一条完整命令可以恢复。

## 验收标准

1. STM32CubeIDE 工程重新构建成功。
2. STM32CubeProgrammer 下载和 verify 成功。
3. 复位后 PC 收到 `H2-READY\r\n`。
4. 连续 10000 次 `H2-PING\r\n` 均收到且只收到 `H2-PONG\r\n`。
5. 未知命令和超长输入均收到 `H2-ERR\r\n`。
6. `H2-` 与 `PING\r\n` 之间停顿 750 ms 时不得返回 `H2-PONG`，随后完整 PING 必须恢复。
7. 先以错误波特率发送数据，等待超过 500 ms 后切回 115200，第一条完整 PING 必须返回 `H2-PONG`。
8. 保存命令、原始结果和未验证项；不宣称电机链路已经完成。
