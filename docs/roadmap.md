# 开发路线

路线按可验证闭环拆分。后续阶段只有在上一阶段安全门通过后开始。

## 阶段 0：工程基线

目标：仓库结构、Docker、CI、文档、仿真和测试入口可复现。

- [x] ROS 2 Humble 工作区与包边界
- [x] Gazebo 差速底盘、LaserScan 与 SLAM Toolbox
- [x] 参数化 URDF/Xacro 与 TF 所有权
- [x] STM32F407ZGT6 板级 `.ioc` 基线
- [x] AI Lite 文档、BOM、环境、协议和验收门

完成标准：新环境可构建、测试；README 不宣称未完成功能。

## 阶段 1：真机底盘（约 2 周）

目标：从 `/cmd_vel` 到双轮闭环，再回到 `/odom` 和 TF。

1. 确认供电、驱动器、电机和编码器电气参数。
2. 冻结 STM32 引脚和 CubeMX 配置。
3. 完成双编码器计数和每轮标定。
4. 完成单电机、双电机开环测试。
5. 完成 100 Hz 双轮速度 PID 和输出限幅。
6. 冻结二进制协议与 500 ms 通信看门狗。
7. 实现 ROS 2 串口驱动、运动学、里程计、TF、诊断和重连。

完成标准：架空与落地测试均可复现；断线停车；无 TF 冲突；闭环误差达到验收文件要求。

## 阶段 2：视觉目标（约 2 周）

目标：稳定发布目标观测，完成“寻找红色物体”的无运动和低速演示。

1. USB 摄像头采集、健康状态和断流恢复。
2. 先实现可测试的红色色块检测。
3. 再接入 YOLO 小模型和目标白名单。
4. 冻结目标观测消息、置信度和时间戳语义。
5. 使用录制视频完成离线回归。

完成标准：无摄像头或检测过期时明确失败；不发布伪检测；目标位置与置信度可复现。

## 阶段 3：任务与 AI（约 2 周）

目标：文字“寻找红色杯子”转为安全状态机并完成搜索闭环。

1. 实现 `IDLE → SEARCH → ALIGN → APPROACH → ARRIVED` 状态机。
2. 本地关键词规则支持中文/英文 `search`、`stop`。
3. 视觉故障、目标丢失和状态超时统一进入停车。
4. 可选接入 LLM，只接受结构化白名单结果。
5. 语音识别只作为文本输入适配器。

完成标准：五次受控演示至少四次完成；任何故障路径最终速度为零。

## 阶段 4：工程化（约 2 周）

目标：可复现、可演示、可交接。

- Docker/CI 全量复现。
- 参数标定记录、接线图和故障手册。
- 单元、协议、Launch、无硬件集成和实物验收。
- 演示视频、系统截图和版本发布说明。

## 暂不实施

micro-ROS、`ros2_control`、机械臂、端到端强化学习、无约束 Agent、多机器人和自行训练大模型不属于 AI Lite MVP。
