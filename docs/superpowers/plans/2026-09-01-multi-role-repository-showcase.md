# OpenRobot-One 多岗位仓库展示实施计划

## 目标

按照已批准的设计，将仓库整理为面向技术支持、FAE、项目交付、实施、机器人系统/硬件测试和售前岗位的统一项目作品集。

## 任务 1：核对展示证据

- 读取现有验证报告、验收标准、协议、架构和测试脚本。
- 只提取能够由仓库文件直接支持的成果和量化数据。
- 检查 CI 当前状态和现有硬件图片。

验收：每项拟展示成果都有明确证据路径；未验证能力不进入已完成成果。

## 任务 2：重构 README

- 建立招聘导向首屏。
- 增加核心成果、岗位能力矩阵、证据入口、验证状态和排障案例。
- 保留工程结构、运行方式、限制和许可证。
- 增加必要徽章和精选硬件图片。

验收：HR 在首屏能看到项目定位、适配岗位、真实成果和深入阅读入口。

## 任务 3：新增技术证据页

- 新建 `docs/project_showcase.md`。
- 汇总验证状态、实测数据、环境、证据、排障案例和交付物索引。
- 使用统一的状态词和问题定位模板。

验收：从 README 最多两次点击可打开每项测试脚本或验证报告。

## 任务 4：整理展示图片

- 视觉检查现有硬件照片。
- 复制 3–4 张最能说明主控、通信和驱动方案的图片到 `docs/assets/showcase/`。
- 使用稳定英文文件名，不修改原始图片。

验收：图片路径可由 Git 跟踪，Markdown 引用正确，内容不包含明显敏感信息。

## 任务 5：验证与发布

- 检查 Markdown 相对链接、图片路径、证据状态和 Git 差异。
- 对文档中的本地相对链接执行存在性检查。
- 提交展示层变更并推送 `main`。
- 在 GitHub 公共页面检查 README、图片、Mermaid 和徽章。
- 在授权能力可用时更新仓库简介和 Topics；否则报告最小手动操作。

验收：本地与远端提交一致、工作区干净、公共页面可访问。本次若未运行 ROS 2 全量测试，明确报告未复验。
