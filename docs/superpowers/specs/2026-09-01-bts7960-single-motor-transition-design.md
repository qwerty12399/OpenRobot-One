# BTS7960 单电机真机轨转向设计

## 1. 目标与结果边界

OpenRobot-One 保留已经验证的 ROS 2 双轮差速仿真轨，同时将当前真机轨永久缩减为单电机架空速度闭环验证台。两条轨道不是互不相关的演示，而是同一差速机器人控制链的不同验证层：

```text
系统层：/cmd_vel -> 差速运动学 -> 左右轮目标 -> Gazebo -> /odom、TF、/scan -> SLAM

执行层：同一差速运动学中的一个轮速目标 -> ROS/PC 台架适配器 -> UART
        -> STM32F407 -> IBT-2/BTS7960 -> 单台 JGA25-370
        -> AB 编码器 -> STM32 单电机速度闭环 -> ROS/PC 遥测
```

当前真机轨不实现或宣称：

- 双电机差速控制；
- 落地直行或原地旋转；
- 真机 `/odom`、`joint_states` 或 `odom -> base_footprint` TF；
- 真机 SLAM、AMCL 或 Nav2；
- 未经实测的编码器计数、电流、稳态误差和停车时间。

双电机底盘只作为远期扩展，不属于当前里程碑或验收条件。

当前项目的完整性由统一的命令语义、参数来源、协议、状态反馈和分层验收保证：仿真证明系统级接口与导航链，单电机台架证明一个真实执行通道，HIL 验证明 `/cmd_vel` 经差速映射后能够驱动真实电机并返回可观测反馈。不得把单通道 HIL 写成双轮真机或整车闭环。

## 2. 已购硬件与证据等级

当前方案围绕以下硬件整理：

- STM32F407ZGT6 开发板；
- ST-Link V2；
- CH340 USB-TTL；
- 一台 JGA25-370、12 V、620 RPM、带 AB 编码器的电机；
- 一块 IBT-2/BTS7960 H 桥模块；
- 12 V / 5 A 适配器及配套 DC 转接线；
- 连接线和端子材料。

本轮三张 IBT-2 商品截图只证明卖家页面的标注，不证明到货模块的芯片真伪、连续电流、逻辑兼容性、排针方向或电气状态。整理时必须区分：

- `照片确认`：图片中可直接辨认的型号、丝印和端子名称；
- `卖家标称`：电压、输入电平、PWM 频率和 43 A 等商品参数；
- `实测确认`：由万用表、示波器、烧录结果或受控实验取得的数据；
- `UNKNOWN`：尚无可靠证据的参数。

三张商品图存在两项必须保留的冲突：

1. 动力电源范围同时写为 `5.5–27 V` 和 `6–27 V`；12 V 位于两者交集，但不能据此确认模块全范围。
2. 两张图对 `RPWM`、`LPWM` 的正反转语义互相颠倒；软件方向只能通过架空低能量脉冲实测冻结。

商品页所称 74HC244 “隔离”只按逻辑缓冲记录，不解释为光耦或隔离电源意义上的电气隔离。STM32 与模块仍需要共地。`43 A` 不作为连续能力或小电机保护依据。

## 3. 当前架构

### 3.1 统一控制契约

仿真和真机台架共享以下语义，不要求共享同一个执行节点：

```text
/cmd_vel
  -> 参数化差速运动学
  -> left_target_rpm / right_target_rpm
  -> 执行端
  -> target_rpm / measured_rpm / encoder_count / state / fault
```

仿真执行端同时消费左右目标；单电机 HIL 通过参数 `bench_channel=left|right` 选择其中一个目标发送给真实电机，另一个目标只保留为模型参考，不伪造硬件反馈。轮径和轮距用于仿真与目标换算，必须标记为仿真参数或实测参数；没有安装轮子时，不能据此宣称真实位移。

统一控制契约至少包含：时间戳、命令序号、通道身份、目标 RPM、实测 RPM、编码器计数、使能状态、运动命令新鲜度、传输状态和故障码。这样后续增加第二套执行通道时可以复用接口和测试，而不改写已有单电机证据。

机器人轮径、轮距和速度限制必须由同一个版本化参数源提供给仿真和 HIL 适配器。建立至少四组固定 `/cmd_vel` 参考向量：零速、直行、原地旋转和混合运动。每组同时验证：

1. 离线差速运动学计算出的左右目标；
2. HIL 适配器输出的选定通道目标与离线结果一致；
3. Gazebo `/joint_states` 中左右轮稳态角速度与同一参考目标在已冻结容差内一致。

该契约测试通过后，才能声称仿真和单电机 HIL 复用了同一控制语义；仅有相同字段名或架构图不算通过。

### 3.2 仿真轨

仿真轨保持现有设计和发布职责：

- Gazebo 差速插件订阅 `/cmd_vel`；
- Gazebo 发布 `/odom` 和 `odom -> base_footprint`；
- `robot_state_publisher` 发布机器人内部 TF；
- SLAM Toolbox 或 AMCL 二选一发布 `map -> odom`。

现有 URDF/Xacro、Gazebo、SLAM、Docker、CI、检查脚本和测试均保留。它们是已验证成果，不因真机硬件缩减而删除。

### 3.3 单电机真机轨

当前单电机台架不作为完整 ROS 底盘执行端，但必须接入统一控制契约。最小数据流为：

```text
ROS/PC 台架适配器
  -> 从 /cmd_vel 映射或直接输入受限目标 RPM
  -> UART 目标转速/停止/心跳
  -> STM32 安全状态机
  -> RPWM/LPWM/R_EN/L_EN
  -> IBT-2/BTS7960
  -> 单台电机
  -> AB 编码器
  -> STM32 计数、RPM、PID
  -> UART 状态/故障/遥测
```

ROS `hardware` Launch 继续作为安全占位入口，不发送任何运动命令。完成 H0–H4 后再实现台架适配器，使用 `/bench/target_rpm`、`/bench/measured_rpm`、`/bench/encoder_count`、`/bench/fault` 和诊断语义。它可以订阅经过限幅的 `/cmd_vel` 并选择一个轮通道，但不发布底盘 `/odom` 或 TF。

### 3.4 分层验证闭环

| 验证层 | 被验证内容 | 真实硬件 | 不得外推 |
| --- | --- | --- | --- |
| ROS/Gazebo 系统层 | `/cmd_vel`、差速运动学、Topic、TF、LaserScan、SLAM | 无 | 真机运动能力 |
| UART/协议层 | 编解码、CRC、序号、超时、错误恢复 | STM32、CH340 | 电机闭环 |
| 单电机执行层 | PWM、方向、编码器、RPM、PID、安全停车 | STM32、BTS7960、电机、编码器 | 双轮一致性和里程计 |
| 单通道 HIL 层 | `/cmd_vel` 到选定轮目标，再到真实反馈和诊断 | 上述全部 | 完整真机底盘、SLAM/Nav2 |

四层证据共同构成一个项目：系统层回答“机器人软件链是否工作”，执行层回答“真实执行通道是否受控”，HIL 层回答“软件命令是否真正到达硬件并返回反馈”。

## 4. 候选 STM32 资源

以下仅是经板卡引出和复用表初筛的候选资源，必须在 CubeMX、实物丝印和无动力电平测试后冻结：

| 功能 | 候选引脚 | 说明 |
| --- | --- | --- |
| `RPWM` | `PB6 / TIM4_CH1` | PWM，启动比较值为 0 |
| `LPWM` | `PB7 / TIM4_CH2` | PWM，启动比较值为 0 |
| `R_EN` | `PB8` | 普通输出，启动为低 |
| `L_EN` | `PB9` | 普通输出，启动为低 |
| 编码器 A | `PA0 / TIM2_CH1` | 编码器模式候选 |
| 编码器 B | `PA1 / TIM2_CH2` | 编码器模式候选 |

`PA9/PA10` 保留给 USART1，`PA13/PA14` 保留给 SWD，`PC13` 保留给状态 LED。`R_IS/L_IS` 首次实验不连接；其比例、最大电压和 STM32 接口方案保持 `UNKNOWN`。

`R_EN`、`L_EN` 分别使用外部 `10 kΩ` 下拉到 GND，使 MCU 复位、未供电或 GPIO 高阻期间保持禁用；阻值和接线必须在实际模块输入电平核验后冻结。不能只依赖应用代码初始化。PWM 引脚在切换到定时器复用前先配置为低电平 GPIO，启动比较值保持 0。

## 5. 安全状态与实验阶段

### H0：装备与机械安全

- 电机可靠固定并架空，不装轮子；
- 人员现场值守，旋转轴周围无松散物；
- 万用表、2 A 保险丝、直流断电开关或急停可用；
- 首次使用可调限流电源，或按受限方案增加串联 12 V / 21 W 灯泡；
- 动力线、端子和绝缘满足电流与机械固定要求。

### H1：断电电气核查

- 按实物逐线确认 `B+`、`B-`、`M+`、`M-` 和控制排针；
- 测量动力输入无明显短路，确认极性和公共地；
- 确认模块 `VCC` 要求、STM32 3.3 V 高电平兼容性和控制脚实际电平；
- 安装并测量 `R_EN/L_EN` 外部下拉，确认 MCU 断电和复位时两个使能脚均为低；
- 确认编码器供电和 A/B 输出不会超出 STM32 输入范围；
- 不以芯片或商品页内部保护替代外部保险丝和限流。

### H2：无动力控制验收

- 不连接电机动力电源；
- 上电、复位、Fault 和错误处理路径均保持 `R_EN=L_EN=0`、PWM 比较值为 0；
- 验证现有 UART H2 基线仍通过；
- 当前 500 ms UART 半包清理不作为电机命令看门狗。

### H3：单次受控脉冲与开环

- 首次只允许一次授权的单方向 `5% / 100 ms` 脉冲；后续每个占空比或持续时间台阶都必须单独重新授权，并受当次测试矩阵的上限约束；
- 使用非阻塞定时到期停车，不依赖串口轮询返回；
- 到期、串口断开、错误、MCU 复位和人工停止均进入统一安全停车；
- 方向语义由实测建立，不照抄冲突的商品图；
- 通过后才逐级进入低占空比开环 RPM 测试。
- 动力电源接通时执行 MCU 复位、串口断开和 PC 测试进程退出，三个场景均不得产生新的 PWM，且使能脚必须回到低电平。

### H4：编码器与闭环

- 手转输出轴三次标定每圈计数，离散度不高于 1%；
- 冻结编码器方向和电机方向符号；
- 100 Hz 速度采样与单电机 PID 不持续振荡；
- 三个受控目标点取已验证安全开环转速范围的约 20%、40%、60%，每点无轮、空载运行 10 s并重复 3 次；
- 每次最后 5 s 作为稳态窗口，误差按 `abs(mean(measured_rpm) - target_rpm) / abs(target_rpm) * 100%` 计算，三次均不高于 10%；
- 稳态窗口峰峰值不高于目标绝对值的 15%，否则判定为持续振荡或反馈异常；
- 只有新的 `SET_MOTOR_RPM`（包括显式零速）刷新 500 ms 运动命令看门狗；独立传输心跳不得延长旧的非零目标；
- 连续 10 次超时试验中，从最后一条有效运动命令到 PWM 为零且 `R_EN/L_EN` 为低的实测延迟均不高于 550 ms；物理转子完全停稳时间单独记录，不混作控制输出关闭时延；
- 所有指标必须来自真实日志，不使用示例值。

任一安全门失败，后续非零输出停止，状态保持 `BLOCKED`。

### H5：ROS 单通道 HIL

- 台架适配器复用与仿真一致的差速运动学参数和公式；
- 从受限 `/cmd_vel` 计算左右目标，并只把 `bench_channel` 对应目标发往真实电机；
- 目标 RPM、实测 RPM、编码器计数、命令序号、延迟和故障状态可同步记录；
- 零速、直行、原地旋转和混合运动四组输入的目标换算与离线参考逐项一致；
- 同一组参考向量下，Gazebo `/joint_states` 稳态轮速与离线目标的容差由仿真基线测试冻结并记录，不使用 HIL 电机动态误差替代契约误差；
- ROS 进程退出、串口断开或命令超时触发真实电机停车；
- 至少记录 1000 个连续命令/反馈样本的端到端延迟 P50、P95、最大值、丢失数和序号异常数；首次验收以真实报告为准，不预填性能数字；
- 不生成虚假的另一轮反馈，不发布真机 `/odom` 或 TF。

## 6. 协议边界

当前真机线协议只覆盖单电机，但字段语义与 ROS 统一控制契约一致：

- `SET_MOTOR_RPM`：设置受限目标转速；
- `STOP`：立即进入安全停车；
- `HEARTBEAT`：只验证传输存活，不刷新运动命令新鲜度；
- `MOTOR_STATE`：返回计数、RPM、目标、输出和状态位；
- `FAULT`：返回协议、电气或控制故障。

命令和状态必须包含可关联的序号或时间信息，使 ROS 端能够验证目标、反馈和超时链路。传输存活状态和运动命令新鲜度是两个独立状态：通信仍在线但运动命令过期时，电机也必须停车。CRC、字节序、载荷长度和测试向量在 PC/STM32 逐字节一致后冻结。双执行通道线协议移入远期扩展；差速运动学保留在 ROS/PC 适配层，用于把统一 `/cmd_vel` 映射为当前选定轮目标。

## 9. 当前开放风险

- 尚无到货 IBT-2 模块正反面实物照片；排针方向和芯片顶标未确认。
- 12 V / 5 A 固定适配器没有可调限流；首次实验仍需要外部保护方案。
- 编码器电平、PPR/CPR、减速比折算计数和实际电机电流未实测。
- 商品页方向定义冲突，不能提前冻结软件正转语义。
- 当前固件只有 H2 UART，不具备安全电机输出能力。
- 当前 ROS 台架适配器尚未实现，统一控制契约仍是已批准设计而非实测成果。

这些风险不阻塞文档与资产转向，但继续阻塞任何电机通电和非零命令。
